# Decisions

1. **Service layer as the API seam.** `lib/services/*` exposes async functions (`conversationService.getConversations()`, `aiService.generateReply()`…) that map raw mock JSON to domain types and simulate latency. Replace the implementations, keep the signatures.
2. **Single client store.** `WorkspaceProvider` (`lib/store/workspace.tsx`) composes per-domain hooks (`use-conversations`, `use-comments`…). It lives in `app/(app)/layout.tsx`, so state survives navigation. Mutations are optimistic, then reconciled with the service response.
3. **Persistence.** AI settings, automations and accounts are saved to localStorage (`creatorai:*.v1`) inside the services, standing in for a server. Conversations, comments and session stats stay in memory so demos are repeatable.
4. **Deterministic mock AI.** `lib/mock/ai-reply-rules.json` drives replies: keyword intent detection (ties go to the conversation's intent), per-automation tone and threshold, avoid-topic deflection, review forced by matching user rules, and a spam `noReply` flag. `variant` changes the template on regenerate.
5. **Analytics = baseline + session.** Static 30-day JSON, with this session's reply counts added to today (`use-analytics.ts`).
6. **Platform-generic types.** `Platform = "instagram" | "youtube" | "tiktok" | "x"`; only Instagram data/UI exist.
7. **Route group `(app)`** for the dashboard shell; `/debounce-demo` sits outside it. `/inbox` reads `searchParams` (dynamic); other pages are static.
8. **Custom Instagram glyph**, because lucide-react 1.x dropped brand icons.
9. **Backend = Next route handlers + PostgreSQL via Drizzle** (`drizzle-orm` + `pg`). Server code lives in `lib/server/` (`db → repositories → services`), and `app/api/*` routes stay thin. Client `lib/services/*` call `/api` with the same signatures. Text IDs keep the mock IDs. Seeded demo data lives in `ws_default`. `DATABASE_URL` goes in `.env` (gitignored); `.env.example` is committed.
10. **Auth = hand-rolled DB sessions, no auth library.** Passwords: `node:crypto` scrypt (N=2^17, r=8, p=1, params stored in the hash). Sessions: random 256-bit token in an HttpOnly, SameSite=Lax cookie (`__Host-` + Secure in prod). The DB stores only its SHA-256 (`sessions.id`). 30-day expiry, renewed when an authed API call lands within 15 days of expiry. CSRF: SameSite plus a `Sec-Fetch-Site`/`Origin` check on non-GET routes.
11. **Tenant = session workspace.** `sessions.workspace_id` is set server-side at login/signup. Each lookup joins `workspace_members`, so a removed membership kills the session. API routes use `authedRoute()` (`lib/server/auth/route.ts`) and scope every query by `auth.state.workspace.id`; they never take a client-supplied workspace ID. Pages call `requireAppAuth()`; `proxy.ts` only checks that the cookie exists. Setup state is per workspace: `workspaces.plan` (picked on /pricing) and whether an Instagram `social_accounts` row exists. `lib/auth-flow.ts` maps that to the next step. The Inbox and `/api/conversations*` require Instagram (`requireInboxAuth` / `requireInstagram`).
12. **Public site + OAuth-shaped Instagram placeholder.** `(marketing)` pages (`/`, `/pricing`) are static and public. The dashboard Overview lives at `/dashboard`. Instagram connect follows the real OAuth shape: `/api/integrations/instagram/connect` sets a single-use HttpOnly `state` cookie, then the provider's consent screen, then `/callback`, which checks `state` and upserts the account into the session's workspace. All provider specifics are behind `InstagramProvider` (`lib/server/integrations/instagram/provider.ts`). For real OAuth, implement it; the placeholder consent page `/onboarding/instagram` then goes away.
13. **Theming = token override.** `@theme` holds the dark values. `:root[data-theme="light"]` redefines the same `--color-*` variables, so components never branch on theme. `ThemeScript` sets `data-theme` before paint, from localStorage (`creatorai:theme`, a display preference, never auth data) or the OS setting. New colors must be tokens or CSS vars, not hex.
